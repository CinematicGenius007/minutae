# Accessibility Audit — `@minutae/ui` Kit

Audit of every component in `libs/ui/src/components/` across mouse, keyboard, screen reader, and high contrast (`forced-colors: active` and `prefers-contrast: more`), conducted against WCAG 2.1 AA.

## Defects fixed in this pass

- **Focus rings under `forced-colors: active`:** Replaced `outline: none` on `:focus-visible` (in `base.css`, `Field.module.css`, `Tabs.module.css`, `List.module.css`, `Hud.module.css`, `Detail.module.css`, `Live.module.css`, `library.module.css`, `TrayPanel.module.css`) with a 2 px transparent outline (`outline-color: Highlight` in forced-colors) so focus rings remain visible when `box-shadow` is stripped.
- **Selected/checked/on states under `forced-colors: active`:** Added system `Highlight` / `HighlightText` / `ButtonText` / `GrayText` styling for `Toggle`, `Checkbox`, `Radio`, `Segmented`, `Tabs`, `NavItem`, `FilterChip`, `LaneRow`, `Progress`, `RecordPill`, `StatusDot`, `Select`/`DropdownMenu`, `PlayerBar`, and floating surfaces (`ConfirmDialog`, `Toast`, `HudPill`, `Tooltip`, `CallPrompt`, `TrayPanel`).
- **`prefers-contrast: more`:** Strengthened `--muted`, `--line`, `--line-strong`, `--control-edge`, and `--destructive` via tokens in `tokens.css` (light and both dark blocks).
- **Token contrast & `--faint` audit:** Added `--control-edge` (`#8A8A85` light, `#6E6E69` dark) for 3:1 control boundaries and readable disabled text; lightened dark `--muted` to `#9A9A94`; switched `--placeholder`, live partial captions (`.partial`, also italic + ellipsis), drag handles, and stat loading dashes off `--faint`; updated dark `--toggle-knob-off` to `var(--ink)` (4.36:1 on `--control-edge`). Added automated WCAG regression tests in `libs/ui/src/styles/tokens.test.ts`.
- **Hit targets (≥ 28 × 28 desktop):** Expanded hit areas without changing visual size via `::after` on `Tag` remove button (22 → 28), quiet/destructive `Button` links, `Toggle` (24 → 28 height), `Checkbox` and `Radio` (18 → 28), `PlayerBar` scrubber (20 → 28), and small screen controls (settings nav links, provider reorder handles, model download cancel, detail speaker/timestamp/moment buttons, tray links).
- **Screen reader & keyboard fixes:**
  - `DropdownMenu`: switched checkable items (`checked !== undefined`) to `Radix.CheckboxItem` (`role="menuitemcheckbox"` + `aria-checked`) and marked decorative check/shortcut spans `aria-hidden`.
  - `HudPill`: moved live-region text from `aria-label` (with `aria-hidden` text) to real DOM text (`mn-sr-only` for listening, visible span otherwise) with `aria-atomic="true"` so screen readers reliably announce state changes.
  - `RecordPill`: announces `"Recording started"` at minute 0, minute counts every 60 s, and `"Recording stopped"` on stop.
  - `Progress`: added fallback `aria-label="Progress"` so `role="progressbar"` is never unnamed.
  - `Segmented`: added `tag` and `disabledReason` (exposed via `aria-describedby` and `title`) and blocked programmatic selection of disabled options.
  - `KeyCap` / `Shortcut`: completed `SPOKEN` map for arrow, Escape, Backspace, and Delete keys.
  - `SearchField`, `Tooltip`, `Checkbox`, `Chip`, `Select`, `PlayerBar`: hid decorative SVGs and redundant trailing shortcut hints from screen readers.
  - `Summaries` (`apps/desktop`): fixed a keyboard trap where `onKeyDown` on the provider reorder handle re-focused the handle on `Tab` as well as `ArrowUp`/`ArrowDown`.
  - `ApiKeyDialog`, `Detail` inline title/speaker rename: restored focus to the opener/trigger button on close and added `aria-describedby` to `ApiKeyDialog`.

## Component Audit & Remaining Gaps

| component | mouse | keyboard | screen reader | high contrast | gap |
|---|---|---|---|---|---|
| `Button` | Click, hover, pressed, disabled (`loading` disables) | Tab, Space/Enter, transparent outline focus ring | Native `<button>`, `aria-busy` on loading, decorative icon/shortcut hidden | Borders and `Highlight` focus survive; disabled uses `GrayText` | Dark `--destructive` (`#F0624D`) on `--raised` (`#2A2A28`, used in dialogs/menus) is 4.49:1 (0.01 below 4.5:1 AA); `--destructive` token was left unchanged per design freeze. |
| `RecordPill` | Click, hover, pressed, disabled | Tab, Space/Enter, visible focus ring | `aria-pressed={live}`, live region announces start, every 60 s, and stop | Idle uses `ButtonText` border/dot; live uses `Highlight`/`HighlightText` + stop square | None. |
| `ConfirmDialog` | Trigger click, overlay click, cancel/confirm buttons | Focus trap, Tab cycles actions, Esc closes, focus returns to trigger (Radix) | `role="dialog"`, `aria-labelledby`, `aria-describedby` (hidden fallback if omitted) | Modal gets `CanvasText` border in forced-colors | Uses `role="dialog"` rather than `role="alertdialog"` for destructive prompts; when opened from a transient hover-revealed trigger that unmounts on confirm (e.g., deleting a Whisper model), focus falls back to `document.body`. |
| `DropdownMenu` | Trigger click, hover highlight, item click | Enter/Space/ArrowDown opens, ↑↓/Home/End/type-ahead navigate, Esc closes, focus returns to trigger | `role="menu"`, `menuitem` / `menuitemcheckbox` (`aria-checked`), shortcuts hidden | Highlighted item uses `Highlight`/`HighlightText`; menu bordered in `CanvasText` | Dark `--destructive` item on `--raised` is 4.49:1 (see `Button`). |
| `TextField` | Click anywhere in box focuses input, hover/error/disabled states | Tab focuses input, standard editing keys | `<label htmlFor>`, `aria-invalid`, `aria-describedby` pointing to help/error (`role="alert"`) | `--control-edge` border + `Highlight` focus outline on `.box:focus-within` | None. |
| `SearchField` | Click box focuses search input | Tab focuses input, standard search editing | `<input type="search">` with `aria-label`, decorative icon and shortcut hidden | `--control-edge` border + `Highlight` focus outline on `.box:focus-within` | No built-in clear (`×`) button; clearing relies on Escape (handled per screen) or manual selection. |
| `Select` | Trigger click opens popover, click selects option | Space/Enter/Arrow opens, ↑↓/Home/End/type-ahead navigate, Esc closes, focus returns to trigger | `role="combobox"`, `aria-expanded`, `role="listbox"`, `role="option"`, `aria-selected`; supports `aria-label`/`aria-labelledby`/`aria-describedby` | `--control-edge` trigger border, `Highlight`/`HighlightText` active row, `CanvasText` menu border | None. |
| `Segmented` | Click selects enabled option; disabled options show `not-allowed` and tooltip | Roving tabindex: Tab enters active option, ←/→ moves between enabled options, skips disabled | `role="radiogroup"` + `role="radio"` (`aria-checked`), disabled option exposes `disabledReason` via `aria-describedby` | Track bordered in `ButtonText`; active segment uses `Highlight`/`HighlightText`; disabled uses `GrayText` | None. |
| `Tabs` | Click activates tab | Tab enters active tab, ←/→/Home/End switch tabs, Tab enters panel | `role="tablist"`, `role="tab"`, `aria-selected`, `role="tabpanel"`, `aria-labelledby`, shortcut hidden | Active tab text and 2 px underline use `Highlight`; focus outline on trigger and panel | None. |
| `Toggle` | Click toggles; 28 × 40 hit target | Tab, Space/Enter toggles, focus ring | `role="switch"`, `aria-checked`; pairs with `<label htmlFor>` | Off uses `ButtonText` border + thumb on `Canvas`; on uses `Highlight` track + `HighlightText` thumb | Requires caller to supply `id` (with `<label htmlFor>`) or `aria-label` (not enforced by TypeScript props). |
| `Checkbox` | Click box or label toggles; 28 × 28 hit target | Tab, Space toggles, focus ring | `role="checkbox"`, `aria-checked="true"\|"false"\|"mixed"`, `<label htmlFor>` when `label` prop used | Unchecked `--control-edge`/`ButtonText`; checked/mixed `Highlight`/`HighlightText` | Standalone `<Checkbox />` without `label` relies on caller passing `id` + `<label>` or `aria-label`. |
| `RadioGroup` / `RadioItem` | Click circle or label selects; 28 × 28 hit target | Roving tabindex, Arrow keys move & select, Space selects | `role="radiogroup"`, `role="radio"`, `aria-checked`, `<label htmlFor>` when `label` prop used | Unchecked `ButtonText` 1.5 px ring; checked `Highlight` 5.5 px ring | Standalone `<RadioItem />` relies on caller passing `id` + `<label>` or `aria-label`. |
| `FilterChip` | Click toggles pressed state | Tab, Space/Enter, focus ring | `<button aria-pressed={selected}>`, optional count included in name | Unselected `--control-edge` border; pressed `Highlight`/`HighlightText` | None. |
| `Tag` | Optional `×` button removes tag (28 × 28 hit target) | Tab reaches `×` button, Space/Enter removes | `aria-label="Remove <text>"` (or custom `removeLabel`), icon `aria-hidden` | Bordered in `CanvasText` in forced-colors; `×` gets `Highlight` focus outline | Focus management after removing a tag is left to the parent screen (typically moves to next tag or input). |
| `Pill` | Non-interactive | Not focusable | Plain `<span>` text | Hairline border repainted to `CanvasText` | None. |
| `KeyCap` / `Shortcut` | Non-interactive | Not focusable | `<kbd>` with `aria-hidden` visual glyphs and `mn-sr-only` spoken key names | `--control-edge` border + shadow; repainted in forced-colors | None. |
| `StatusDot` | Non-interactive | Not focusable | Dot `aria-hidden`, always paired with visible or SR-only label | `ok`/`onair` filled `Highlight`; `off` hollow `Canvas` with `GrayText` border | None. |
| `Progress` | Non-interactive | Not focusable | `role="progressbar"`, `aria-valuemin/max/now`, `aria-label` (defaults to `"Progress"`) | 5 px `CanvasText`-bordered track with `Highlight` fill | None. |
| `Spinner` | Non-interactive | Not focusable | `role="status"` + `aria-label` when `label` provided, else `aria-hidden` | Border repainted to `CanvasText` | None. |
| `ToastProvider` / `ToastSurface` | Click action button; swipe down dismisses | Radix toast region hotkey (`F8`) focuses viewport; Tab reaches action; Esc dismisses | Live announcement via Radix Toast; `altText` set on action | Bordered in `CanvasText`, action button has `Highlight` focus outline | Default 4 s auto-dismiss may be short for users with motor/reading disabilities when an action button ("Undo") is present (Radix pauses on hover/focus, but does not expose a persistent-toast preference). |
| `HudPill` | Non-interactive (`pointer-events: none`) | Never takes focus (by design) | `role="status"` (`polite`) or `role="alert"` (`assertive` for errors), `aria-atomic="true"`, real DOM text | Bordered in `CanvasText`; dot/bars forced to `CanvasText` | None. |
| `Tooltip` | Hover opens after 400 ms | Focus opens immediately, Esc dismisses | Linked via Radix `aria-describedby`; shortcut glyph `aria-hidden` | Bordered in `CanvasText` | Tooltip cannot be hovered directly (`pointer-events` default dismisses on pointer leave toward tooltip if gap crossed quickly, WCAG 1.4.13 hoverable edge case on Radix default `disableHoverableContent={false}` is handled by Radix, though trigger must be focusable). |
| `GroupLabel` | Non-interactive | Not focusable | Semantic heading (`h2`–`h4`, default `h3`) with optional count | Ink rule repainted to `CanvasText` | None. |
| `SettingRow` | Clicking title focuses control when `htmlFor` set | Flows to control in DOM order | `<label htmlFor>` links title to control | Hairline border; disabled title uses `GrayText` | `description` is not automatically wired via `aria-describedby` to the opaque `control` ReactNode; callers must wire `aria-describedby` manually when the description is essential to understanding the control. |
| `LaneRow` | Click anywhere on row activates | Title is `<button>` (avoids nested interactive elements with status-lane actions); Enter/Space activates | Button name is title (or `aria-label`); `aria-current` set when `selected` | Selected row gets 2 px `Highlight` border; focused title button gets `Highlight` outline | Row metadata (time, subtitle, people, duration, status) is outside the title `<button>`, so screen readers navigating by Tab hear only the meeting title unless navigating in browse mode. |
| `Sidebar` / `NavItem` / `MicStatus` / `Wordmark` | Click nav items | Tab, Enter (links) / Space+Enter (buttons), focus ring | `<aside>` + `<nav aria-label>`, `aria-current="page"`, shortcut hidden; `MicStatus` has `role="status"` | Active nav item uses `Highlight`/`HighlightText` | No built-in "Skip to main content" link inside `Sidebar` (lives at app shell level, outside `libs/ui`). |
| `PageHeader` / `Stat` / `EmptyState` | Non-interactive (except `EmptyState` `action` slot) | Flows to interactive children | `<header>` + `<h1>`, `EmptyState` uses `<h2>` | Standard `Canvas`/`CanvasText` | `Stat` renders value above caption as `<div>`s rather than `<dl>`/`<dt>`/`<dd>`, so value and caption are read sequentially rather than as a term/value pair. |
| `Waveform` | Non-interactive | Not focusable | `role="img"` + `aria-label` | Bars inherit `CanvasText` (played/unplayed colour distinction collapses in forced-colors) | In `forced-colors: active`, played vs unplayed waveform bars cannot be distinguished by colour alone (purely decorative; `PlayerBar` exposes exact numeric progress). |
| `PlayerBar` | Play/pause button, range scrubber (28 px tall), speed button | Tab through Play → Seek (←/→/Home/End) → Speed → Extra | `role="group" aria-label="Playback"`, play/pause `aria-label`, range `aria-label="Seek"` + `aria-valuetext`, speed `aria-label` | Play bordered in `ButtonText`; scrubber track `ButtonText` + thumb `Highlight`; focus outlines visible | Scrubber step is fixed at `1000` ms (1 s), which is fine for short calls but coarse/slow for hour-long meetings without PageUp/PageDown step customization. |
